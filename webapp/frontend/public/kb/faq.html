FAQ & troubleshooting

Frequently asked questions

General

Which engines and versions are supported?

PostgreSQL 13+ (including RDS, Aurora, and Cloud SQL) and MySQL 8 / MariaDB. The collector degrades gracefully when optional statistics are missing and tells you exactly how to enable them.

Do you need access to my database?

No. You run the collector yourself, inside your environment. It connects with a read-only session, reads statistics views only (never table data), and prints its own SHA256 so you can verify what you executed. See Security & privacy.

What data leaves my environment?

A single JSON file of normalized metrics — query shapes with every literal replaced by ?, table/index statistics, and a whitelist of settings. Hostnames are hashed by default. You can open the file and read every byte before uploading.

Is this automated advice?

Findings come from deterministic rules with named numeric evidence, and every report is reviewed by a human before delivery. Recommendations always come with a staging-first test plan; nothing touches your database automatically.

Collector problems

The capabilities line is missing query_stats

Per-query statistics aren't enabled. This is the single most valuable input, so it's worth turning on:

  • PostgreSQL → Enable pg_stat_statements
  • MySQL / MariaDB → Enable performance_schema digests

After enabling, let a normal workload run for at least a day, then re-run the collector.

ModuleNotFoundError for psycopg or pymysql

The database driver isn't installed. Install the one for your engine:

pip install "psycopg[binary]"   # PostgreSQL
pip install pymysql             # MySQL / MariaDB

Permission denied reading statistics views

The collector account is missing statistics grants. Use the minimal read-only grants in the PostgreSQL or MySQL guide. The account never needs SELECT on your data.

Upload & report problems

"not a valid dbdoctor snapshot" on upload

The file wasn't produced by a current collector, or was edited after generation. Regenerate it with pg_collect.py or mysql_collect.py and upload it unmodified. The maximum upload size is 50 MB.

My audit shows "failed" with a 'charmap' codec can't encode… error

This was a bug in an older build on Windows hosts (the default text encoding couldn't represent the minus sign used in the score breakdown). It's fixed — all report I/O is now written as UTF-8. Update to the latest build, restart the backend, and re-upload the snapshot. Previously failed jobs don't retry themselves.

The report shows a "report" button instead of "pdf"

PDF rendering uses a headless Chromium that is a separate download from the Python package. When it isn't installed, the audit still completes and you get the identical HTML report instead — the content is the same. To enable PDFs on the server, run once: 

python -m playwright install chromium

Alternatively the server can disable PDF rendering entirely (DBDOCTOR_ENABLE_PDF=false) and rely on the HTML report. A PDF failure never fails an audit whose report was generated.

My report is stuck in "expert review in progress"

That's expected — every report is held for human review before release, usually within one business day. Once approved, the status flips to ready and the download buttons appear.

Still stuck?

Start a new audit from the New audit page, or review the report guide. The collector prints a precise fix for most misconfigurations it detects.
