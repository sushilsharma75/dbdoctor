Getting started

What DBDoctor is & how it works

DBDoctor turns one sanitized statistics snapshot from your PostgreSQL or MySQL database into a prioritized, evidence-backed performance audit — without anyone ever touching your credentials or your data.

The core idea

Most performance tools ask you to hand over a connection string or install an agent that talks to a third party. DBDoctor does neither. You run a single, readable Python script inside your own environment. It opens a read-only session, reads statistics views only, strips every literal value at the source, and writes a snapshot.json file. You upload that file — and only that file — to get your report.

The three steps

Step 01

You run one read-only script

Download a single Python file — pg_collect.py or mysql_collect.py — that you can read in about ten minutes. It connects with a read-only session, collects statistics views only (never table data), and prints its own SHA256 so you can verify exactly what you executed. See Collect a PostgreSQL snapshot or Collect a MySQL snapshot.

Step 02

You upload the sanitized snapshot

The snapshot is normalized metrics: query digests (with literals already replaced by ?), table and index sizes, index usage counts, and a short list of whitelisted settings. No row data, no parameter values, hostnames hashed by default. You can open the file in any editor and read every byte before uploading.

Step 03

You get an expert-reviewed report

A deterministic rule engine produces prioritized findings, each backed by named numeric evidence, and computes a 0–100 health score. A human reviews every report before it is released to you. You receive an HTML/PDF report plus a tasks.md of paste-ready tickets for your tracker. See Understanding your report.

What makes the findings trustworthy

  • Deterministic rules, not guesses. Findings come from explicit rules with tunable thresholds — the same snapshot always produces the same report.
  • Evidence-backed numbers. Every finding cites the metric that triggered it. The optional AI narration may only rephrase those numbers, never invent new ones.
  • Human review hold. No report is auto-delivered. Each one is held for expert review — usually released within one business day.
  • Staging-first fixes. Recommendations always come with a test plan; nothing touches your database automatically.

Which databases are supported

PostgreSQL 13+ (including RDS, Aurora, and Cloud SQL) and MySQL 8 / MariaDB. The collector degrades gracefully when optional statistics are missing and tells you exactly how to enable them. See the FAQ for details.
